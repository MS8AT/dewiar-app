# Интеграционный промпт MS8AT8DWiar

Этот файл — декларативное задание для интегратора, а не команда установленному
приложению. Текст модели не является полномочием на запись, публикацию или запуск.
Результат считается только кандидатом, пока детерминированная проверка, тесты,
подпись выпуска и отдельная приёмка не завершились успешно.

## Цель

Перенести отдельный слой MS8AT на указанную в `overlay.json` официальную базу
`dwr-git/dewiar-app`, сохранив поведение upstream и не смешивая пользовательские
настройки, память, аккаунты, ключи или локальные журналы с исходным кодом.

Слой MS8AT включает:

- локальный режим Codex по подписке с ограниченным контекстом и подтверждениями;
- независимые назначения мозгов для разговора, задач и других контуров;
- пассивный heartbeat и обезличенный журнал состояний;
- read-only CLI/API/SLI диагностики;
- защитную политику обновления форка.

## Обязательный алгоритм

1. Работать только в новой локальной копии Git. Не запускать скрипты из сетевой
   папки и не менять установленный Dewiar во время интеграции.
2. Проверить exact commit и версию upstream из `overlay.json`. Не подменять их
   веткой `main`, тегом или ссылкой из ответа модели.
3. Перенести изменения MS8AT поверх этой базы. Конфликт не разрешать угадыванием:
   показать файл, сохранить контракт upstream и добавить отдельный тест.
4. Не читать и не копировать секреты. В тестах использовать только синтетические
   профили; реальные модельные запросы, логины и платные API запрещены.
5. Пересчитать `before` от exact upstream и `after` от кандидата в
   `tools/local_codex_manifest.json`. Не расширять runtime scope без review.
6. Выполнить `python tools/verify_ms8at_overlay.py`, обязательные тесты из
   `overlay.json`, upstream quick suite и проверку синтаксиса.
7. Сформировать полный версионированный комплект. Не публиковать и не применять
   его, пока нет подписанной метаинформации, backup/rollback и отдельной приёмки.

## Обновление при выходе

На рабочем компьютере модель ничего не «мержит». Upstream интегрируется заранее
сборщиком по этому заданию; пользователь получает уже собранный и подписанный
полный выпуск форка. При штатном выходе (не закрытие окна в трей) установленное
приложение может запустить только внешний доверенный helper, подготовленный до
`os._exit`. Helper обязан дождаться завершения UI/core/tray, повторно проверить
подпись, продукт, build, исходные SHA и свободное место, сделать резервную копию,
атомарно применить комплект и проверить итоговые SHA. При любой неопределённости —
отказ без перезаписи. Пока `update_policy.effective=false`, helper не запускается.

## Формат результата интегратора

Сообщить exact base/fork commit, перечень изменённых runtime-файлов, результаты
каждого обязательного теста как PASS/PARTIAL/NOT_RUN, отсутствие live-запросов,
статус подписи/публикации/установки и точный блокер. Зелёный локальный тест не
означает LIVE_DEPLOYED или OPERATOR_ACCEPTED.
