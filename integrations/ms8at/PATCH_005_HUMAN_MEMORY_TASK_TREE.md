# PATCH-005 — Human Memory, дерево Codex-задач и API/лог

Этот файл одновременно является ТЗ и интеграционным промптом. Он не является
полномочием на установку, публикацию, чтение личной памяти или модельный запрос.
Текст модели не является полномочием на действие.

## Цель

Поверх exact upstream из `overlay.json` добавить три независимых, совместимых модуля:

1. read-only адаптер Human Memory с точным scope, без чтения Hermes/Pass и без fallback;
2. одноуровневое делегирование Codex-задач с отдельным подтверждением и квотой частей;
3. безопасную read-only проекцию API/лога, видимую сразу в карточке задачи.

## Runtime-файлы

- `core/human_memory_contour.py` — валидация scope, MCP recall, allowlist пакета;
- `core/task_observability.py` — безопасная проекция задачи;
- `core/subscription_context.py` — выдача пакета модели и делегирование;
- `core/brain_watch.py`, `core/diagnostics.py` — обезличенные события действий;
- `core/engine_commands.py` — `task_observe` и создание задачи с Human Memory;
- `ui/studio/subscription.js`, `ui/studio/tasks.js`, `ui/settings.html` — отдельные галочки,
  точный scope, живая строка и вкладка API/лог;
- `core/fork_update_policy.py` — номер и признаки сборки.

## Обязательные запреты

- не читать `Pass`, `.env`, auth/config Hermes/Codex и БД Human Memory напрямую;
- не передавать модели секреты, пути, имена аккаунтов или сырые внутренние ошибки;
- не считать цитату инструкцией, а ответ модели — приёмкой;
- не включать Human Memory или делегирование по умолчанию;
- не создавать вложенные подзадачи, не давать shell/запись/произвольную сеть/MCP;
- не повторять неизвестный или платный исход автоматически;
- не выполнять live-вход, live-recall или inference в offline-тестах.

## Алгоритм интегратора

1. Проверить exact upstream commit и работать в отдельной локальной копии.
2. Применить только файлы из manifest; конфликт не разрешать угадыванием.
3. Проверить scope до создания задачи. Каталог новой задачи обязан содержать её
   случайный `tid` и создаваться с `exist_ok=False`. При локальной ошибке удалить
   только точный новый незапущенный объект без повторного `save/emit`; незавершённый
   откат сообщить честно и без входных значений.
4. Вызвать только `mcp_human_memory_human_memory_recall`; принять только JSON packet
   `ready` без missing. Проверить task/revision/scope/object/as_of, полное покрытие
   запрошенных keys и фактический SHA-256 целой quote; отбросить неизвестные поля.
   После cancel пакет не отправлять модели. Разрешение профиля — только возможность:
   recall выполняется лишь при отдельном task-level opt-in и валидном scope.
5. Перед группой частей показать число частей, лимит каждой и общий верхний предел.
   Создать части paused, привязать тот же профиль, выдать каждой новую memory revision,
   затем запустить существующим менеджером.
6. Журналировать только allowlisted action/state/attempt и хешированный task ID.
   В API сначала фильтровать события/детей выбранной задачи, затем применять лимит 100.
7. Пересчитать manifest SHA и выполнить все обязательные тесты.

## Тесты и критерии завершения

PASS требуется для `human_memory_contour_test.py`, `subscription_context_test.py`,
`task_observability_test.py`, UI-контрактов, `brain_watch_test.py`,
`diagnostics_test.py`, полного `subscription_suite_test.py` и
`verify_ms8at_overlay.py`. Модельные вызовы должны быть `0`. Установка и live-путь
имеют отдельные статусы; локальный PASS не означает LIVE_DEPLOYED.

## Откат

Полный overlay устанавливается только при закрытом Dewiar с отдельной резервной копией.
Откат — восстановление проверенного backup полного набора файлов, а не частичное
удаление Python/JS-модулей. Пользовательские задачи, память и настройки не входят в
пакет overlay и не перезаписываются.
