# Изоляция Dewiar/Codex через WireGuard — план, не реализация

Цель: до десяти независимых сетевых профилей Dewiar, каждый с явным включением
и отсутствием выхода в обход своего туннеля. Сначала один пилот.
Десять профилей не означают десять одновременно работающих VM или аккаунтов:
нагрузку, число одновременных подключений и условия сервисов нужно согласовать.

## Предлагаемая схема

Для Windows-клиента основной кандидат — отдельная Windows VM на профиль:
Dewiar, собственный Codex и браузер входа внутри неё → WireGuard → MikroTik →
явно выбранный разрешённый выход. Отдельная переменная proxy или CODEX_HOME
не является сетевой изоляцией. Linux network namespace — альтернативный путь,
но текущая реализация хранилища Codex Windows туда не переносится автоматически.
Принцип namespace описан в [WireGuard](https://www.wireguard.com/netns/).

При общем VPN endpoint можно рассмотреть один WireGuard-интерфейс MikroTik
и десять peers с непересекающимися адресами клиентов. Это не готовая конфигурация:
версия RouterOS, модель роутера, адреса, VLAN, endpoint и доступные выходы пока
не определены. Peer WireGuard не равен профилю авторизации ChatGPT.
Параметры сверяются с [документацией MikroTik](https://manual.mikrotik.com/docs/virtual-private-networks/wireguard/).

## Импорт QR или конфигурации

Изображение QR разбирается локальной библиотекой, без отправки модели или
облачному OCR. Разрешён только формат WireGuard и известные поля; команды
PreUp/PostUp/PreDown/PostDown и неизвестные расширения отклоняются.
До применения показываются endpoint, адреса и маршруты с замаскированными
ключами; установка, запуск и изменение сети требуют отдельного подтверждения.
PrivateKey хранится только в защищённом системном хранилище, не в Git/журналах.
Профили отключены по умолчанию; импорт не поднимает соединение.

## Приёмка и этапы

- [ ] Инвентаризация конкретного роутера и хоста, схема управления и резервная копия.
- [ ] Автономный парсер QR/.conf: отрицательные тесты, лимиты размера, отсутствие секретов в логах.
- [ ] Одна VM/один peer, независимый вход; никаких общих auth-файлов.
- [ ] Запрет прямого выхода до старта VPN, при сбое, смене маршрута и после перезагрузки.
- [ ] Проверка DNS и IPv6; разрешить только нужный VPN endpoint снаружи туннеля.
- [ ] Запрет связи между профилями и с управляющей LAN, кроме отдельно разрешённого управления.
- [ ] Политика маршрутов без резервного перехода в main; учёт FastTrack.
- [ ] Два профиля: независимая остановка, потеря endpoint, нагрузка и отсутствие пересечения данных.
- [ ] После принятия пилота — измерение ресурса для десяти профилей и постепенное включение.
- [ ] Отдельно разрешённый короткий запрос модели; проверка лимита и отсутствие автообхода.
- [ ] Проверяемый откат правил, VM и peers без потери доступа к роутеру.

FastTrack требует особой проверки при policy routing: нельзя считать установленный
маршрут доказательством отсутствия обходного трафика.
Основание — [packet flow RouterOS](https://help.mikrotik.com/docs/spaces/ROS/pages/328227/Packet+Flow+in+RouterOS).
Все перечисленные меры — проектные требования, их работа на реальном оборудовании
не проверена. VPN не отменяет политики организации, условия OpenAI или
ошибку `3p_delegated_access_policy_denied`.
