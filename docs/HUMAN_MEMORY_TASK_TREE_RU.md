# Human Memory, дерево Codex-задач и API/лог

## Что добавлено

Это отдельный контур поверх Dewiar 0.39.8. Он не заменяет локальное «Обо мне» и
не превращает существующий `core/graph.py` в embedding-сервис. Локальный граф Dewiar
остаётся лексическим, а Human Memory подключается только через уже настроенный
read-only MCP-сервер `human_memory` и его инструмент `human_memory_recall`.

Для каждой новой Codex-задачи человек отдельно включает Human Memory и задаёт точные
`session_id`, `object_key`, 1–16 `keys`, `since`, `as_of`. Dewiar не читает конфиги
Hermes/Codex, каталог `Pass`, `.env` или БД напрямую и не угадывает отсутствующий scope.
Если MCP не подключён, пакет неполный либо задача остановлена, запрос Codex не уходит.
В prompt попадают только целые цитаты с evidence ID, SHA-256 и ограниченной
метаинформацией. Цитаты считаются данными, а не инструкциями или полномочием.
Разрешение Human Memory в профиле само по себе память не включает: без отдельной
галочки и точного scope задача работает как обычная Codex-задача. Ответ MCP принимается
только при совпадении task/revision/scope/object/as_of, полном покрытии keys и SHA-256
реального текста каждой цитаты.

## Делегирование

Корневая Codex-задача при отдельной галочке может предложить от 1 до 4 независимых
подзадач за один запуск, до 16 за жизнь корневой задачи. Человек видит верхнюю границу
расхода и подтверждает каждый запуск группы. Каждая часть использует тот же профиль,
имеет отдельную квоту и новую revision Human Memory. Вложенное делегирование запрещено.
Результаты собираются существующим `wait_parts`; shell, запись в проект, сеть и
произвольные MCP-инструменты этому режиму не выдаются.
Создание частей и первый запуск выполняются под блокировкой родителя с повторной
проверкой stop/delete; незапущенные части откатываются без повторного сохранения.

## API и журнал

Команда ядра `task_observe` — локальная read-only проекция одной задачи. Она показывает:

- хешированные task/profile/parent ID;
- состояние, число шагов и квоту Codex;
- прямых дочерних задач и их состояния;
- состояние read-only коннектора Human Memory и отпечаток scope;
- до 100 событий `task_state`, `task_quota_granted`, `task_action`.

Фильтр выбранной задачи и её прямых детей применяется до лимита 100, поэтому старые
чужие задачи не скрывают свежие события и части. Одинаковые названия не смешивают
журналы: каталог задачи содержит её уникальный `tid`.

Промпты, ответы, цели, аргументы действий, пути, имена аккаунтов, точные session/object/
keys и секреты в этот API не входят. В карточке задачи краткая строка API/лог видна
сразу; вкладка «API / Лог» показывает безопасную таблицу и JSON. `completed` означает
только завершение вызова, не приёмку результата.

## Границы и статус

- Источник истины для персональных цитат: подключённый человеком Human Memory MCP.
- Источник истины для состояния задачи: локальная задача и журнал `brain_watch`.
- Модель Codex не получает инструменты Human Memory напрямую; пакет получает Dewiar.
- Нет скрытого fallback, автоповтора, фоновой синхронизации или записи в Human Memory.
- Установка выполняется полным проверенным overlay при закрытом приложении с backup.
- Live-вход, live-recall и платный inference не являются частью offline-проверок.

## Приёмка

Обязательны синтетические тесты точного scope, отсутствующего MCP, неполного пакета,
остановки после чтения, allowlist доказательств, наследования scope с новой revision,
квот/подтверждений подзадач, редактирования лога и интерфейса. Затем — overlay verifier,
полный offline suite и отдельный review. Live-recall выполняется только с точным
контекстом задачи и отдельным осознанным запуском.
