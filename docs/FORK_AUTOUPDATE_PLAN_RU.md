# Самообновление MS8AT8DWiar: границы и план внедрения

Цель: приложение узнаёт о новом проверенном выпуске форка, скачивает его, затем
обновляет собственные файлы при безопасном штатном закрытии. Пользовательские
настройки, память, входы и Python не входят в замену. Самостоятельный merge
произвольного upstream-кода моделью не является частью автообновления.

## Реализовано сейчас

- [x] Диагностические CLI/API и SLI для offline/локальных проверок.
- [x] В действующем единственном потоке updater сохранён поиск upstream-версии
  и заметок через штатный manifest. Это discovery, не установка форка.
- [x] `source_managed=True` у Engine: upstream EXE больше не скачивается как
  обновление форка; прямой `_download` тоже отказывает.
- [x] В реальном Api закрыты install_update, _install_update_win и run_installer
  для обычного установщика. Старый cached EXE не становится допустимым.
- [x] В интерфейсе разделены версия upstream и состояние нашего канала;
  `unconfigured` не выдаётся за «установлена последняя версия форка».
- [ ] Доверенный fork-feed и ключ издателя. Не настроены и не проверены.
- [ ] Скачивание, staging, отложенный helper, автоматическое применение нового форка.

Таким образом, **автоустановка сейчас не реализована/не включена**. Текущая защита
не даёт штатному апдейту затереть дополнения; рабочий ручной способ с backup остаётся
в [LOCAL_CODEX_RU.md](LOCAL_CODEX_RU.md). Новые внешние сервисы/задачи планировщика
не создавались. Это отдельный этап, не ложный зелёный статус готовности.

## Источник и доверие

Предлагаемый publisher — проверенные Releases `MS8AT/dewiar-app`, а upstream
`dwr-git/dewiar-app` — вход для интегратора. Выбор источника и режима установки
запрошен у оператора; отсутствие ответа не считается включением автоустановки.
Не использовать произвольный URL из ответа модели, тег без release, ветку main
или последнюю дату файла как доверенное обновление.

GitHub Releases API позволяет отдельно получать опубликованные выпуски и assets;
обычные Git-теги не равнозначны release. Документация проверена 2026-10-22:
[GitHub Releases](https://docs.github.com/en/rest/releases/releases).
SHA с того же неподписанного сайта проверяет целостность, но не независимую личность
издателя. Для unattended режима нужен закреплённый trust root, подписи, срок действия
метаданных и защита от rollback/replay. Основа дизайна:
[TUF overview](https://theupdateframework.io/docs/overview/).

## Минимальная архитектура

| Компонент | Обязанность | Граница |
|---|---|---|
| Upstream discovery | Версия и список изменений | Не скачивать/не исполнять upstream EXE |
| Сборщик выпуска | Интегрировать upstream, прогнать тесты, собрать полный комплект | Отдельная публикация после review; не внутри приложения |
| Publisher | Подписать release metadata, опубликовать versioned assets | Закрытый ключ вне Git/app/пакета; bootstrap/ротация отдельно |
| Один updater приложения | Проверять, скачивать, верифицировать, готовить pending | Egress/local-only, bounded network, без второго scheduler |
| Доверенный внешний helper | После выхода проверить базу, backup, установить, проверить | Не исполнять helper из нового архива до доверия; без kill |
| Receipt/SLI | Зафиксировать этап, build/hash/ошибку и состояние проверки | Нет секретов; unknown не переходит автоматически в retry |

Простой вариант: автоматическое обнаружение/скачивание, применение только кнопкой.
Целевой вариант: те же проверки, но применение при штатном выходе, если пользователь
включил соответствующую политику. Наличие одной пустой панели не означает idle:
учитываются core, tray, задачи, голосовые вызовы и занятые файлы.

## Контракт выпуска

Метаданные должны фиксировать product/channel/platform, монотонный build,
upstream version, exact source commit, срок действия, минимальный installer protocol,
поддерживаемую предыдущую базу и зависимости. Нужны размер и SHA архива, полный список
разрешённых файлов с размерами/SHA, обязательные features (`codex_local`, `brain_routes`,
`brain_watch`, `diagnostics_v1`), key ID и подпись. Формат подписи не изобретать: выбрать
поддерживаемую библиотеку/TUF и закрепить версии после отдельной проверки.

В текущем встроенном Python нет cryptography/PyNaCl. Не добавляли пакеты молча.
Выбор verification dependency, ключей и первого release — отдельный release gate.
Ни ключи из Pass, ни account tokens для этого не читаются и не переиспользуются.

## Последовательность установки

1. Read-only status и check раздельны. Сетевая проверка не означает download/apply.
2. Скачать в отдельный локальный staging, с лимитами времени/размера, HTTPS,
   разрешёнными хостами redirects; ошибка не трогает рабочий app.
3. Проверить подпись, срок, build, продукт, platform, features, lock dependencies.
   Запретить zip-slip, дубли имён без учёта регистра, symlink/junction/hardlink,
   device/ADS-пути, архивные бомбы, чужие файлы за пределами app allowlist.
4. Сохранить durable `verified`, точный hash и политику `pending_close`.
5. Helper вне заменяемого app ждёт реальный штатный выход. Таймаут/новая активность
   откладывает установку, не завершает процесс принудительно.
6. Системный mutex для конкретного app + повторная проверка политики, архива,
   исходных SHA, процессов и свободного места непосредственно перед записью.
7. Сохранить старые файлы + receipt до первой замены. Каждый файл переносить атомарно;
   build marker — последним. Неизвестные локальные изменения дают отказ, не overwrite.
8. Проверить SHA всего нового комплекта и offline smoke. Только потом `installed`.
   Рестарт/возобновление пользовательских задач — отдельная политика, не автоматом.
9. При прерывании — `rollback_required`, следующий запуск блокирует смешанную версию.
   Проверяемый rollback использует сохранённые исходные SHA; unknown не повторять.

## Targets и критерии приёмки

| Target | Результат | Gate |
|---|---|---|
| U01 | Подтверждён источник, режим, точный writer/publisher | Ответ оператора, read-only проверка repo/releases |
| U02 | Версионированная схема + trust bootstrap | Тесты valid/invalid signatures, expiry/replay/downgrade |
| U03 | Reproducible package на основе нового upstream | Full suite, обязательные features, секретов в архиве нет |
| U04 | Download/staging | Network denial, corrupt/oversize/redirect/paths tests |
| U05 | Отложенный helper/rollback | Закрытие/tray/race/crash/изменённая база/backup tests |
| U06 | UI/API статусов и политики | Раздельные check/download/apply; false-success tests |
| U07 | Один разрешённый canary на тестовой копии | Receipt + hashes + запуск; без модельного запроса |
| U08 | Production opt-in | Подписанный опубликованный выпуск, rollback rehearsed |

До U08 запрещено маркировать автообновление работающим. Не использовать GitHub push
или публикацию release как побочный эффект теста. Полный upstream run_quick и
реальная независимая release-приёмка остаются необходимыми перед публичным выпуском.
