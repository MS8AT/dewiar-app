# Несколько мозгов, контуры и локальное сердце

Дополнение к Dewiar 0.39.2. Профиль — это именованная настройка существующего
провайдера, а не новый сервер или агент. Можно создать несколько профилей одного
провайдера. Автоматического опроса всех профилей, голосования и запасного аккаунта нет.

## Как пользоваться

1. Откройте «Мозг». Добавляйте обычные модели прежними кнопками, Codex — кнопкой
   «Добавить Codex по подписке». Дайте каждому понятное имя в его настройках.
2. Радиокнопка профиля выбирает основной мозг разговора. В блоке «Мозги по контурам»
   отдельно назначьте задачи, черновики навыков, встречи/суфлёр и дневник.
   «По основному мозгу» сохраняет прежнее поведение. Нажмите «Сохранить назначения».
3. Для Codex сначала выберите его аккаунт и модель и включите необходимые разрешения
   конкретного профиля, отправку текста и подтверждение Usage. Назначение не выдаёт
   разрешения, не входит в аккаунт и не запускает задачу. Запросы могут расходовать лимит.
4. В том же блоке смотрите «Сердце и журнал»: состояние последних вызовов, время,
   последний сигнал, состояния задач и события. Видимая вкладка обновляет локальные
   метаданные раз в 5 секунд; кнопка обновления тоже не обращается к модели.

Добавление неактивного профиля и переименование не проверяют активную модель.
Обычное явное переключение основного провайдера сохраняет прежнюю проверку Dewiar.
Если назначенный профиль удалён, контур останавливается с понятной ошибкой,
а не выбирает другой профиль. Для восстановления назначьте существующий или
явно выберите наследование основного. Настройка модели задач в обоих разделах общая.

## Архитектура и границы

Используется существующий реестр `llm.profiles`, без второго Manager/Router или SDK.
Это реализация принципов наблюдения проекта AI_WorckBook, не подключение его runtime.
Основной вариант — явные назначения; простой вариант — оставить все контуры
«По основному мозгу». Модельные протоколы и закреплённый CLI этим этапом не меняются.

| Компонент | Вход → результат | Ограничение и проверка |
|---|---|---|
| `brain_routes` | роль + настройки → копия профиля | Удалённый ID без fallback; permissions Codex; unit-тесты |
| Существующие потребители | выбранный профиль → ответ | Чат/задачи/дневник/встречи/черновики; старые consent/cancel остаются |
| `brain_watch` | начало/сигнал/конец вызова, событие задачи → SQLite | Нет inference, retry, restart; неизвестность не подменяется успехом |
| `studio/brains.js` | локальный status → текст панели | Имена через textContent; DOM-тесты; не визуальная приёмка |

«Ответ завершён» означает окончание вызова, не проверку правильности и не приёмку
задачи. Нет свежего сигнала дольше порога (30–900 секунд, по умолчанию 90) —
**неизвестный прогресс**, а не доказанное зависание. В частности, Codex может долго
думать без промежуточных событий. Незавершённые вызовы прежнего запуска отображаются
с неизвестным исходом. Heartbeat ничего не возобновляет и не лечит автоматически.

Записываются инструментированные текстовые вызовы общего `stream_events` и прямого
адаптера Codex, а также изменения статуса/счётчика шагов задач. Вложенный вызов
адаптера не считается вторым запросом. Это не журнал всех операций ОС: речь, embeddings,
изображения, вызовы иных транспортов, изменение настроек и каждый внутренний шаг модели
не покрыты. Память остаётся частью действующего контекста/разрешений, отдельный мозг
для embeddings не добавлен. Самопроверка/обучение задачи используют её профиль и бюджет.

## Данные и безопасность

Журнал: `STATE_DIR/brain-watch.sqlite3`, обычно
`%LOCALAPPDATA%\Dewiar\brain-watch.sqlite3`. Настройки и база принадлежат текущему
пользователю ОС; это не новая многопользовательская серверная система с RBAC.
Несколько Windows-пользователей должны иметь отдельные каталоги состояния/входы.
Профили одного пользователя — логическое разделение, не граница безопасности.
Операции одного Codex-профиля по-прежнему защищены существующим mutex.

В новом журнале нет запросов, ответов, аргументов инструментов, ключей, адресов,
текста ошибок или названий задач. ID профилей/задач хешируются; время, статус, роль,
число шагов и локальный ID вызова сохраняются. Имена профилей показываются только
из настроек в локальной панели. Старые журналы самого Dewiar не изменены.

Храним последние 5000 событий и до 500 последних вызовов плюс текущие незавершённые;
панель показывает последние 100 вызовов/событий и до 100 задач. Старые неизвестные
сессии тоже ограничены. SQLite может сохранять выделенный размер файла после ротации.
Отключение журнала останавливает регистрацию новых вызовов и событий задач;
уже зарегистрированный вызов завершает свою запись. История не стирается.
При ошибке базы показывается неполное покрытие; модель не повторяется из-за журнала.

## Проверка и установка

`python -B tests/subscription_suite_test.py` — из локальной копии, с Node.js.
Новые тесты покрывают имена/ID, контуры, отсутствие скрытого fallback/сетевого probe,
permissions, callback, отсутствие секретов, конкурентные потоки, ротацию, поздние
сигналы, рестарт с неизвестным исходом, отказ БД и локальные UI-команды.
Порог приёмки этих тестов — ноль failures; live-ответ не выводится из offline PASS.

Установка и проверяемый откат — [LOCAL_CODEX_RU.md](LOCAL_CODEX_RU.md).
Для уже модифицированной 0.39.2 используйте полный `upgrade_local_release.py`
с новым планом/backup, не установщик дополнения на чистую базу.
Не запускайте скрипты с сетевого диска. Перед установкой закрыть приложение;
после ошибки не запускать до проверки или отката. Настройки/токены не копируются.

Дата проверки: 2026-10-22. Новые model ID/API не выбирались; доступность аккаунтов
и live-инференс не проверялись. Ограниченный следующий сценарий — ручная проверка
панели; запрос модели только с отдельным разрешением пользователя.
