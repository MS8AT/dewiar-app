# CLI, диагностический API и SLI

Предоставлены оба небольших слоя — CLI-команды и показатели SLI.
Ни один из них не вызывает модель, не запускает задачи и не
публикует API наружу. Нового HTTP-сервиса/порта нет: используется существующий
WebSocket ядра, только `127.0.0.1`, с отдельным ограниченным scope `diagnostics`.

## Команды

В установленной Windows-копии из PowerShell:

```powershell
$cli = "$env:LOCALAPPDATA\Programs\Dewiar\app\core\dewiar-cli.cmd"
& $cli test
& $cli api
& $cli status
& $cli brains
& $cli journal
& $cli sli
```

`test` — пять локальных smoke-проверок на временной базе; `api` — описание протокола.
Они работают при закрытом Dewiar, без чтения токена/личных настроек. Это не полный
набор тестов и не проверка доступа к Codex. Полный offline-набор из локального checkout:
`python -B tests/subscription_suite_test.py` (нужен Node.js).

Остальные команды требуют запущенного нового ядра. Они читают существующий token
из каталога настроек, но никогда не печатают его. Для нестандартного размещения:
`--port 8765 --token-file C:\Local\DewiarConfig\token`. Значение токена нельзя
передавать аргументом или помещать в отчёт. CLI не создаёт/не меняет token.

Ответ — JSON; exit 0 означает успешный обмен/тест, не здоровье модели.
Exit 2 — команда недоступна или проверка не прошла; сырой текст исключения скрыт.
В Windows не запускайте скрипты из Z/UNC: используйте установленную или локальную копию.
Для сборки используйте Git checkout с действующим `.gitattributes`: Windows launcher
хранится в рабочей копии как ASCII/CRLF, и manifest проверяет именно эти байты.
Source ZIP нельзя считать эквивалентным проверенному install-пакету без сверки SHA.

## Контракт API v1

Первое сообщение после подключения к локальному WebSocket:

```json
{"cmd":"hello","scope":"diagnostics","token":"<прочитать из защищённого локального файла>"}
```

Сервер отвечает только `{"type":"hello","data":{"limited":true,"scope":"diagnostics"}}`.
Полный `hello` с настройками и событиями разговоров этому клиенту не отправляется.
Токен страницы звонков не даёт этот scope. Подписки на события отсутствуют.

Запрос и ответ:

```json
{"id":1,"cmd":"diagnostics_read","args":{"action":"sli","args":{}}}
{"type":"reply","id":1,"ok":true,"data":{"schema":1,"action":"sli","...":"..."}}
```

Поддержаны `status`, `brains`, `journal`, `sli`; параметры `args` пока только `{}`.
Иные команды, настройки, shell, создание задач, inference, update/download отвергаются.
`diagnostics.dispatch(host, action, args)` — тот же пассивный Python API для тестов.

Поля выводятся по белому списку: хешированные ID, категории провайдеров, привязки
контуров, признаки настроенной модели, boolean-разрешения, состояние наблюдателя
и счётчики. Нет ключей, имён, адресов, названий моделей/задач, промптов и ответов.
Локальный token остаётся полноправным секретом ядра: этот scope ограничивает соединение,
но не превращает master-token в безопасный ключ для чужих клиентов.

## Что означают SLI

- Выборка — до 100 последних сохранённых вызовов, не вся история и не фиксированные сутки.
- `success_ratio = completed / (completed + failed)`. Прерванные, выполняющиеся
  и неизвестные исходы не считаются успешными. При отсутствии знаменателя — `null`.
- p50/p95 — длительности завершённых/ошибочных/прерванных вызовов, nearest-rank;
  не TTFT и не SLA. Недостоверные длительности исключаются и считаются отдельно.
- Пустой журнал → `no_data`, ошибка чтения → `unknown` и метрики `null`, не «100%».
- `availability=not_measured`, `acceptance=unknown`: завершённый ответ не доказывает
  корректность результата или доступность сервера сейчас.

Проверки: синтетические входы, secret-field projection, пустой/недоступный журнал,
неизвестные команды, scope без full hello и событий, неверный token, запрет upgrade
из токена звонка, отказ CLI на старом ядре. Live-сценарий с личным token не выполнялся.
